What actually happened

  • The "forgot password" tool responded differently for real vs. fake usernames — that let you confirm root_ops was a real account without needing any credentials.
  • The server built the login query as ... WHERE username = '<your input>' AND password = '<your input>', and strips the literal -- sequence out of your input first.
  • SQLite treats an unclosed /* block comment as "ignore everything from here to the end of the statement" — so /* comments out the rest of the query just as effectively as -- would have, and the filter never even looks for it.

How to prevent this for real

  • Use parameterized queries / prepared statements — never string-format user input into SQL. No amount of keyword-blacklisting closes every hole; SQL has too many equivalent ways to express the same trick.
  • Don't let secondary features (password reset, signup, "check username availability") reveal account existence through different response text, timing, or status codes.
  • Hash passwords (bcrypt/argon2) so injection alone can't compare against a known plaintext value anyway.
