Objective

Tejas built a quick internal "config import" tool for the team's deploy pipeline at /lab5/import. It just parses whatever YAML you paste in — get it to reveal the flag. There's also a basic keyword filter in front of it; the obvious first payload you'll think of is blocked.

Why this happens in the real world

YAML isn't just a data format — Python's yaml.load() (without the safe_ prefix) can be told, via special tags inside the YAML itself, to construct arbitrary Python objects and even call functions with attacker-chosen arguments. If a config-import feature uses the full loader on YAML a user controls, the "config file" stops being data and becomes a way to make the server run code the developer never wrote.

This lab simulates the "call a function" step instead of actually executing anything, so you can see the mechanism completely safely.

Where to start
  • Research the YAML tag syntax for constructing arbitrary Python objects/calling functions if it's new to you — this is a well-documented, named technique.
  • You're looking for a function capable of running an arbitrary system command. There's more than one standard-library way to do that — if your first idea gets blocked by the filter, that doesn't mean the technique is dead, it means you need a different function name that does the same thing.
  • Once you trigger it, the argument you pass is the command. Aim it at a file called flag.txt.
