What actually happened

  • The loader used here understands YAML tags that mean "call this function with these arguments" — the shape is !!python/object/apply:module.function [args].
  • A keyword filter blocked the single most obvious function name for "run a shell command" — but Python's standard library has more than one function that does the same thing, and the filter only knew about one of them.
  • In a genuinely vulnerable app using yaml.load() without safe_load, this same tag would run a real shell command, not a simulated one. This lab intercepts it so nothing actually executes.

How to prevent this for real

  • Always use yaml.safe_load() for any YAML that isn't 100% trusted. safe_load only ever builds plain Python types — it has no concept of "call this function," so there's no function-name blocklist to maintain (or fail to maintain completely) in the first place.
  • Keyword/name blocklisting is almost always incomplete — there are usually multiple equivalent ways to reach the same dangerous capability.
  • The same class of bug exists in other serialization formats too: Python's pickle module is far worse (deserializing untrusted pickle data is essentially always RCE) — never unpickle data from an untrusted source.
